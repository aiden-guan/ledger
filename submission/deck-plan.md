# LedgerLens — Idea to Demo

## Narrative and layout plan

1. **Follow the money.** A spacious paper cover, title on the left, original procedural tree on the right. Establish the metaphor and the financial investigator.
2. **Small leaks, specific proof.** One large first-year opportunity figure above a restrained ledger of four findings. Distinguish one-time and recurring value; disclose fictional records.
3. **One invoice. Paid twice.** Actual reconstructed Figma evidence screenshot dominates the right; short explanatory sequence anchors the left. Link to the clickable prototype.
4. **A fix, ready for judgment.** A large prepared-action screenshot on the left, a compact human-approval statement on the right. Link to the working product.
5. **The machine earns trust.** Blue background, a horizontal sequence from records to deterministic checks to grounded explanation to owner approval. White text, orange evidence marker.
6. **The actual path was a loop.** Paper background with a staggered path: existing code → reconstructed Figma Design → exported tokens → runnable code → Figma Slides. Clearly distinguish earlier lost Figma work from this session.
7. **Stage 01 / Ideation.** Large stage number at left; a short actual-session log at right. Source and decision outputs visible along the bottom. Approximate current-session timing; evaluator rating identified.
8. **Stage 02 / Prototyping.** Native prototype screenshot at left; concise log and linked artifact at right. State coverage, typography, evidence, approval, and actual rework.
9. **Stage 03 / Handoff.** Palette and semantic-token specimen across the upper area, exported CSS below, stage log on the right. Demonstrate a real design-to-code transfer.
10. **Stage 04 / Code generation.** Dark background with actual checks at left and bounded log at right. Clarify external code generation, Make upload failure, and native prototype fallback.
11. **What broke, what changed.** Three independent editorial rows: large SVG payload → coordinate packing; clipped auto layout → screenshot-driven fix; denied Make upload → native prototype plus packaged source. No fabricated user-study or time-saving claim.
12. **Try it. Trace it. Reuse it.** Paper closing with large artifact links, repository, prototype, and live application. Explicit remaining requirements: insert native prototype embed, attach video, verify Anyone sharing, and confirm all team members' Edu status.

## Shared design constants

- Fonts: Geist Medium/Regular; Geist Mono Regular for measurements, metadata, and code.
- Paper #f6f4ee, ink #111111, blue #1662e6, readable orange #a7470e, surface #fafaf8, muted #62625c, divider #d9d7d0.
- Recurring motif: a single orange record square following the evidence path, with the source-generated pixel tree on the opening and closing.
- Broad margins, deliberate asymmetry, one main idea per slide; alternate open layouts with evidence-rich layouts.
- Reusable append-first frame/text/rectangle helpers and a fixed color/font preamble in every batch.

## Evidence boundaries

The user reports earlier Figma use and lost files. Historical tools, timings, ratings, and artifacts are not reconstructed as fact. Stage logs describe this reconstruction/refinement session, use approximate overlapping stage timings, and mark ratings as agent assessments. The native prototype has four linked states and source-derived artwork. The runnable HTML prototype uses exported Figma tokens and real engine output. Browser playback remains unverified; local model checks are recorded separately. Make import was blocked before source import by the execution environment's network connection.
